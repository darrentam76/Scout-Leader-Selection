# Input Data Schema & Parameters

### 1. Leader Profile (Collected from Replit / Lovable App - approx. 20 leaders)
Each leader entry contains:
- `name` (String)
- `gender` (Enum: M / F)
- `years_of_experience` (Enum: 1, 2, 3, 4-6, 7-10, 11-15, 16-20)
- `work_background_scout_skill` (Enum: Select 1 of 20 Master Data Options above)
- `target_ic_count` (Enum: 2, 3, 4) — *Hard cap max 3*
- `preferred_partners` (List of Leader Names)
- `preferred_events` (List of Event IDs / Names from CSV)

### 2. Activity / Event List (CSV - 25 Events)
Each event entry contains:
- `event_id` & `event_name`
- `event_date` (Status: TBC / Tentative)
- `required_ic_count` (Default: 2 to 3 ICs)
- `required_skill_category` (Mapped to relevant Scout skills)

---

# Hard Constraints & Optimization Rules

1. **IC Workload Cap (Hard Constraint):**
   - Every leader MUST be assigned as IC **at least 2 times** and **at most 3 times**.
   - If a leader inputs `target_ic_count = 4`, automatically cap it to **3** to ensure fair workload distribution across the troop.
   - Total available IC slots across 25 events = 50 to 75 slots.

2. **Seniority Definition & Pairing ("舊帶新" Rule):**
   - **Junior Leader:** 1 or 2 years of experience.
   - **Senior Leader:** **3 years or above** (3, 4-6, 7-10, 11-15, 16-20).
   - **Rule:** Every event MUST have at least **ONE Senior Leader** ($\ge 3$ years experience) as IC. NEVER assign an event with only Junior Leaders.

3. **Interest & Expertise Matching:**
   - **Priority 1:** Match leader's explicit `preferred_events` list.
   - **Priority 2:** Match leader's `work_background_scout_skill` with event's `required_skill_category` (e.g., First Aid skill $\rightarrow$ First Aid Badge Day; Pioneering skill $\rightarrow$ Camp Construction).

4. **Partner Preference:**
   - Attempt to pair leaders listed in `preferred_partners` for the same event, provided doing so does NOT violate Rule 2 (Senior-Junior Pairing) or Rule 1 (Workload Cap).

5. **Handling TBC Event Dates:**
   - Organize scheduling by `event_id` sequence and category, acknowledging dates are TBC.

# Step-by-Step Processing Workflow

1. **Ingest & Validate Data:** Parse leader entries and 25 event records. Convert `years_of_experience` to Senior/Junior status.
2. **Anchor Senior Leaders:** Ensure every event has 1 Senior Leader ($\ge 3$ years experience) assigned first.
3. **Fill Remaining Slots:** Fill the 2nd and 3rd IC positions using preference lists, skill alignment, and partner requests.
4. **Audit Bounds:** Verify every leader's IC count is strictly within $[2, 3]$.
5. **Report & Interact:** If data is missing or constraints collide, explicitly ask the user for clarification.
